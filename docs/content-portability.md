# Content capability portability

This is an evidence-based snapshot of the current publishing engine, not a product roadmap.
It records what authored source survives across open.blog's parser and model, generated HTML,
no-JavaScript reading, feeds, Admin preview, and syndication adapters. It fulfills the audit in
[#107](https://github.com/journey-to-code-org/open.blog/issues/107).

## Reading the matrix

- **Implemented** means open.blog has an explicit source contract and tested output for the
  capability. A destination may still flatten presentation that it does not natively understand.
- **Partial** means useful content survives, but at least one surface treats it as ordinary prose or
  HTML, omits structured meaning, or requires JavaScript for the full experience.
- **Planned** means there is no first-class parser, model, or renderer contract in this revision.
  Ordinary Markdown can describe the idea, but that does not make the capability shipped.

The generated post body is the common path for native pages, RSS and JSON Feed. Admin preview uses
the same site model and document renderer as a build. Syndication instead sends either absolute-URL
Markdown or rendered body HTML according to the destination, so destination-specific semantics are
not guaranteed. See the [feed implementation](../crates/openblog-core/src/feeds.rs), [Admin preview
endpoint](../crates/openblog-cli/src/admin.rs), and [syndication adapters](../crates/openblog-cli/src/syndication.rs).

## Safety, failure scope, and compatibility

Authored Markdown, front matter, raw HTML, sidecars, imported content, and remote responses are
source-boundary input. Validation reports identify the affected source or capability; unknown
content profiles are preserved and fall back to article rendering with a warning instead of
rewriting the source. The relevant behavior is covered by [content-profile fallback
tests](../crates/openblog-core/tests/content_profiles.rs), [source-aware evidence
tests](../crates/openblog-core/tests/research_profiles.rs), [credit-sidecar validation
tests](../crates/openblog-core/tests/contributors.rs), and [safe URL handling](../crates/openblog-cli/src/safe_http.rs).
Authored raw HTML is preserved rather than sanitized, so it remains a trusted-author boundary;
feeds and syndication destinations may additionally sanitize or reject it.

Admin preview is generated into a bounded authenticated preview cache and never saves the edited
document as a side effect. URL source preview requires an explicit save after inspection.
Syndication defaults to a dry run; validation and canonical preflight occur before remote writes,
and failed targets do not update private state. These boundaries are documented in [Using the
Admin](admin.md#test-a-theme-before-publishing), [Automated cross-posting](cross-posting.md#built-in-command),
and the [syndication safety criteria](specs/automated-syndication.md#safety-acceptance-criteria).

Legacy posts remain articles by default, legacy recipe markers still resolve to the recipe profile,
unknown front-matter fields remain preserved, and an unknown profile falls back without changing
authored source. The byte-for-byte legacy recipe regression lives in [content profile
tests](../crates/openblog-core/tests/content_profiles.rs). This audit changes documentation and link
validation only; it does not migrate canonical content or change native page output.
